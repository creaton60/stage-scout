# stage-scout

> Naver Map 데이터와 현장 사진을 근거로 공연 장소를 선정하고, 무대·관객 배치도를 설계하는 시스템.

공연 일자와 규모를 넣으면 → 지도에서 후보지를 찾고 → 그날의 태양·기상·접근성으로 순위를 매기고
→ 현장에서 찍어온 사진으로 실제 지형을 읽어 → 무대와 관객석 배치안을 만들어 준다.

## 왜 만드나

야외 공연 장소 선정은 지금 사람 머릿속에서 일어난다. 공연 당일 오후 5시에 관객이 태양을
정면으로 보게 되는지, 나무가 무대 절반을 가리는지, 2,000명이 실제로 들어가는지는 가봐야 알고,
가봐도 그 판단이 문서로 남지 않는다. 이 시스템은 **그 판단에 근거를 붙이고 재사용 가능하게** 만든다.

## 구조

```
apps/
  api/     Python 3.12 + FastAPI. 헥사고날(포트-어댑터) 구조
  web/     React + TypeScript. 지도 위 배치 편집 UI
docs/
  requirements.md          요구사항 정의서
  architecture/            헥사고날 가이드 + ADR
  domain/glossary.md       용어사전
  planning/                로드맵 + 스프린트별 계획
```

자세한 구조와 작업 규칙은 [CLAUDE.md](CLAUDE.md) 참고.

## 시작하기

```bash
cd apps/api
pip install -e ".[dev]"
pytest
```

## 개발 계획

6주 / 1주 단위 스프린트 6회. 스프린트마다 브랜치 하나와 PR 하나.

| # | 목표 | 산출 |
|---|---|---|
| S1 | 기반 구축 · 도메인 모델링 · 리스크 스파이크 | 공연 등록 수직 슬라이스 |
| S2 | Naver Map 연동 · 후보지 수집 | 지도에서 후보지 검색 |
| S3 | 공연 일자 기준 적합도 평가 | 근거 붙은 장소 순위 |
| S4 | 현장 사진 → 지형·장애물 분석 | 가용 영역 폴리곤 |
| S5 | 무대·관객 배치 최적화 | 배치안 3개 |
| S6 | 배치도 시각화 · 출력 | PDF 배치도 |

전체 계획은 [docs/planning/roadmap.md](docs/planning/roadmap.md).

S1 준비 단계. 도메인 모델과 포트 정의, 의존 규칙 테스트가 들어가 있고
