# 요구사항 정의서 — stage-scout

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 (S1 계획 시점) |
| 최종 수정 | 2026-09-05 |
| 개발 기간 | 6주 / 1주 단위 스프린트 6회 |

## 1. 배경과 문제

야외 공연 기획자는 지금 이렇게 일한다.

1. 지도와 검색으로 후보지를 눈대중으로 고른다.
2. 현장에 나가 사진을 찍고 줄자로 재며 감으로 무대 위치를 잡는다.
3. 관객석은 엑셀과 파워포인트로 대충 그린다.

문제는 **판단 근거가 사람 머릿속에만 있다는 것**이다. 공연 당일 오후 5시에
관객이 정서향 태양을 정면으로 보게 되는지, 나무 그늘에 무대 절반이 가리는지,
예상 관객 2,000명이 실제로 들어가는 면적인지는 가보기 전엔 모른다.
그리고 가봐도 그 판단이 문서로 남지 않아 다음 공연에 재사용되지 않는다.

## 2. 목표

**공연 일자와 규모를 입력하면, 근거가 붙은 장소 순위와 배치도를 만들어 낸다.**

| 목표 | 성공 지표 |
|---|---|
| 장소 선정 시간 단축 | 후보 5곳 비교 기준 반나절 → 10분 |
| 판단 근거 문서화 | 모든 점수에 사람이 읽을 수 있는 근거 문장 1개 이상 |
| 배치 설계 자동화 | 현장 사진 업로드 후 5분 내 배치안 3개 |
| 재현성 | 같은 입력 → 같은 배치안 (난수 고정) |

## 3. 사용자

| 역할 | 하는 일 | 이 시스템에서 얻는 것 |
|---|---|---|
| 공연 기획자 | 공연 등록, 후보지 선정 | 일자별 적합도 순위 |
| 무대 감독 | 현장 답사, 무대 배치 결정 | 사진 기반 배치안 |
| 운영/안전 담당 | 관객 동선, 수용 인원 관리 | 구역별 수용 인원, 통로 확보 도면 |

## 4. 기능 요구사항

### FR-1. 공연 등록 (S1)
- FR-1.1 공연명, 일자, 시작·종료 시각, 예상 관객 수를 등록한다.
- FR-1.2 무대 형태(정면형/돌출형/사방형)와 규격(가로·세로·높이)을 등록한다.
- FR-1.3 셋업·철수 소요 시간을 등록한다.

### FR-2. 지도 기반 후보지 수집 (S2)
- FR-2.1 키워드와 지도 영역으로 공연 가능 후보지를 검색한다. (Naver Map)
- FR-2.2 주소 ↔ 좌표 변환을 지원한다.
- FR-2.3 후보지의 부지 경계 폴리곤과 면적을 확보한다.
- FR-2.4 대중교통 최근접 거리, 주차 가능 대수, 차량 진입 가능 여부를 수집한다.
- FR-2.5 후보지를 특정 공연에 연결하고 목록으로 관리한다.

### FR-3. 공연 일자 기준 적합도 평가 (S3)
- FR-3.1 공연 일자·시간대의 태양 궤적(고도·방위)을 계산한다.
- FR-3.2 관객이 태양을 정면으로 보는 **역광 위험**을 판정한다.
- FR-3.3 공연 일자의 강수 확률·풍속·기온 예보를 반영한다.
- FR-3.4 예상 관객 수 대비 면적 충분성을 평가한다.
- FR-3.5 위 항목을 가중 합산해 후보지를 **순위와 근거 문장**으로 제시한다.

### FR-4. 현장 사진 기반 지형 분석 (S4)
- FR-4.1 현장 사진을 업로드한다. (복수 장)
- FR-4.2 EXIF 에서 촬영 위치·방위·화각을 추출한다. 없으면 수동 지정한다.
- FR-4.3 사진에서 장애물(수목, 전주, 건물, 경사, 수면)을 검출한다.
- FR-4.4 사진 픽셀 좌표를 지도 좌표로 정합한다.
- FR-4.5 무대·관객석을 놓을 수 있는 **가용 영역 폴리곤**을 산출한다.

### FR-5. 무대·관객 배치 최적화 (S5)
- FR-5.1 가용 영역과 장애물을 제약으로 무대 위치·방향 후보를 생성한다.
- FR-5.2 태양 궤적(역광), 풍향(음향·구조물)을 제약으로 반영한다.
- FR-5.3 관객 지점별 시야각·거리·가림 여부를 계산한다.
- FR-5.4 관객 구역을 나누고 구역별 수용 인원을 산출한다.
- FR-5.5 통로·비상 동선 면적을 확보한다. (구역 면적의 20% 이상)
- FR-5.6 서로 다른 배치안 3개를 점수·근거와 함께 제시한다.

### FR-6. 배치도 출력 (S6)
- FR-6.1 배치도를 지도 배경 위에 렌더링한다.
- FR-6.2 무대 위치·방향, 관객 구역, 통로, 수용 인원을 표기한다.
- FR-6.3 PDF 로 내보낸다.

## 6. 제약과 가정

### 제약
- Naver Map API 는 호출량·비용 한도가 있다 → 캐시 필수.
- Naver Map 은 부지 경계 폴리곤을 직접 제공하지 않는다 → 공공데이터 병행 (ADR-0004).
- 기상 예보는 통상 10일 이내만 신뢰 가능 → 그 밖의 일자는 평년값으로 대체하고 명시한다.

### 가정
- 현장 사진은 지면이 대체로 평면이다 → 호모그래피 정합이 성립한다.
  (경사지에서는 정확도가 떨어짐을 UI 에 표시한다.)
- 공연은 야외에서 열린다. 실내 공연장은 범위 밖.
- 관객은 입석 또는 단순 좌석 배치이며, 고정 좌석 구조물은 다루지 않는다.
