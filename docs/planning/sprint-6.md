## 목표

**시스템 안의 배치안을 현장에서 쓸 수 있는 도면으로 꺼낸다.**
아무리 좋은 배치안도 무대 감독 손에 종이로 가지 않으면 쓰이지 않는다.
그리고 6주간 쌓인 것을 데모 가능한 상태로 다듬는다.

## 끝나면 보여줄 수 있는 것

공연 등록 → 후보지 검색 → 순위 확인 → 사진 업로드 → 배치안 생성 → **PDF 배치도 다운로드**
까지 한 번에 흐르는 데모.

## 설계 사항

- [ ] **도면 레이아웃 설계** — 축척, 방위 표시, 범례, 치수선, 수용 인원 표기 위치
- [ ] **인쇄 규격** — A3 기준. 현장에서 접어 쓸 수 있는 정보 밀도
- [ ] **가중치 조정 UI 설계** — S3 에서 미룬 항목. 기획자가 축별 가중치를 조정하고
      순위 변화를 즉시 본다
- [ ] **관측성 설계** — 외부 API 호출 실패율, 분석 소요 시간, 배치 생성 시간 지표
- [ ] **에러 UX 정리** — 6주간 쌓인 실패 케이스(API 장애, EXIF 부재, 배치 불가)의 사용자 문구 통일
- [ ] **인수인계 문서 구조** — 운영 문서, 남은 과제(Known Issues), 다음 단계 제안

## 개발 사항

- [ ] 배치도 렌더링 (FR-6.1) — Static Map 배경 + 무대·구역·통로 오버레이
- [ ] 표기 요소 (FR-6.2) — 무대 위치·방향, 구역별 수용 인원, 통로, 축척, 방위
- [ ] PDF 내보내기 (FR-6.3)
- [ ] `ExportLayoutUseCase` 구현
- [ ] 라우터 `GET /layouts/{id}/export.pdf`
- [ ] 가중치 조정 UI + 재평가 연동
- [ ] E2E 테스트 — 등록부터 PDF 까지 전 구간
- [ ] 성능 튜닝 (NFR-1, NFR-2 미달 항목)
- [ ] 관측성 — 구조적 로깅, 주요 지표 수집
- [ ] 운영 문서 · Known Issues · 다음 단계 제안서

## 검증할 사항

- [ ] **E2E: 공연 등록 → 후보지 검색 → 순위 → 사진 업로드 → 배치안 → PDF** 전 구간 통과
- [ ] PDF 축척이 실제 거리와 맞다 (도면상 10m 가 실제 10m)
- [ ] 방위 표시가 진북 기준으로 맞다
- [ ] 구역별 수용 인원 합계가 배치안의 `total_capacity` 와 일치한다
- [ ] A3 인쇄 시 치수·범례가 읽힌다 (실제 출력해서 확인)
- [ ] 가중치를 바꾸면 순위가 즉시 바뀌고, 근거 문장도 함께 갱신된다
- [ ] NFR-1(평가 3초), NFR-2(사진 10장 5분) 달성 여부를 측정값으로 보고한다
- [ ] 전체 테스트가 네트워크 없이 통과한다 (`USE_REAL_MAP=false`)
- [ ] 의존 규칙 테스트가 여전히 통과한다 — **6주 뒤에도 아키텍처가 살아 있는지**
- [ ] 시크릿이 코드·커밋·로그에 없다
- [ ] 미달성 항목이 Known Issues 에 솔직히 적혀 있다

## 반영되는 기능

- **FR-6.1** 지도 배경 위 배치도 렌더링
- **FR-6.2** 무대·구역·통로·수용 인원 표기
- **FR-6.3** PDF 내보내기
- (S3 이월) 가중치 조정 UI
