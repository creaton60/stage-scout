# Sprint 5 — 무대·관객 배치 최적화

| | |
|---|---|
| 주차 | W5 |

| 브랜치 | `sprint-5-layout` |
| 선행 | S3 (환경 점수), S4 (지형 제약) |

## 목표

**앞의 네 스프린트가 모이는 지점.** 지형(S4)이 어디에 놓을 수 있는지를 정하고,
환경(S3)이 어느 방향이 나은지를 정한다. 이 스프린트는 그 둘을 합쳐
실제 무대 위치·방향과 관객 구역을 만들어 낸다.

## 끝나면 보여줄 수 있는 것

후보지 하나를 고르면 배치안 3개가 나온다 — 각각 무대가 어디에 어느 방향으로 서고,
관객 몇 명이 어느 구역에 들어가며, 왜 이 배치인지 근거가 붙어서.

## 설계 사항

- [ ] **탐색 전략 설계** — 가용 영역 격자 샘플링 + 방위 15° 단위. 조합 폭발 관리
- [ ] **제약 조건 정리** — 하드 제약(가용 영역 이탈, 장애물 침범, 통로 20% 미확보)과
      소프트 제약(역광, 풍향, 시야각)을 분리. 하드는 후보에서 제외, 소프트는 감점
- [ ] **시야선 모델** — 시야각 60° 초과 감점, 거리 80m 초과 감점, 장애물 가림은 배제
- [ ] **관객 구역 분할 규칙** — 무대 거리대별 구역, 입석/좌석 밀도, 통로 폭
- [ ] **비상 동선 규칙** (FR-5.5) — 구역 면적의 20% 이상, 외곽 접근 경로 확보
- [ ] **배치안 다양성 규칙** — 3안이 서로 충분히 다르도록. 점수 1~3위가 거의 같은 배치면 의미 없다
- [ ] **재현성 보장** (NFR-3) — 난수 시드 고정, 동점 시 결정적 tie-break

## 개발 사항

- [ ] 통로·비상 동선 생성 (FR-5.5)
- [ ] 배치안 점수화 — `SIGHT_LINE_QUALITY`, `OBSTACLE_PENALTY` 축 추가
- [ ] 배치안 다양성 필터
- [ ] `GenerateLayoutService` 구현 (FR-5.6)

## 검증할 사항

- [ ] 생성된 무대가 **가용 영역 안에** 있다 (하드 제약, 100% 단언)
- [ ] 무대·관객 구역이 **장애물과 겹치지 않는다** (기하 교차 0)
- [ ] 관객 구역 총 면적의 20% 이상이 통로로 확보된다 (FR-5.5)
- [ ] 총 수용 인원이 예상 관객 수를 충족한다. 미달 시 그 사실이 근거 문장에 나온다
- [ ] 역광이 심한 방향의 배치안이 상위에 오지 않는다 (S3 점수 연동 확인)
- [ ] 배치안 3개가 서로 유의미하게 다르다 (무대 위치 또는 방위 차이 임계값 초과)
- [ ] **같은 입력 → 같은 배치안** (NFR-3, 시드 고정 후 10회 반복 동일)
- [ ] 가용 영역이 무대보다 작을 때 "배치 불가"를 이유와 함께 돌려준다 (빈 결과 아님)
- [ ] 모든 배치안에 근거 문장이 있다 (NFR-4)
- [ ] 도메인 서비스가 **외부 API 없이** 단위 테스트된다 (헥사고날의 실질 이득 확인)

## 반영되는 기능

- **FR-5.1** 무대 위치·방향 후보 생성
- **FR-5.2** 태양·풍향 제약 반영
- **FR-5.3** 관객 시야각·거리·가림 계산
- **FR-5.4** 관객 구역 분할 및 수용 인원 산출
- **FR-5.5** 통로·비상 동선 확보
- **FR-5.6** 배치안 3개 제시
